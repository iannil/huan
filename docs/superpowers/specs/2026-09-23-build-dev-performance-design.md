# build / dev 性能优化第一批

日期：2026-09-23。用户已同意上一轮性能优化方向和实施顺序。

## 设计

先建立可复现基准、dev 变更集合与调度基础、进程内 Markdown 缓存。保留完整输出构建与插件调用，以免未声明的模板/插件依赖造成旧页面。真正的页面级依赖失效、搜索条目缓存、跨进程缓存、多语言并行在后续阶段实现，本批不宣称完成。

Markdown 缓存位于 build.Options，dev 生命周期内复用，各语言可共享。先执行 shortcode，再对原始正文、展开正文、Markup 配置分别哈希形成键；值只有 HTML、Plain、Summary、WordCount，不保留 Page 指针。使用有容量上限的 LRU，错误不缓存。短代码每次执行以观察其外部依赖，插件页面/输出 hook 每次仍执行。

Watcher 保留完整且去重的变更路径，并保留旧 OnChange 回调兼容。取消时停止待触发计时器。串行 rebuild 调度保留构建中发生的全部变更及手工全量请求，消除 atomic busy/pending 交接窗口。只有全部变更均在 content 下且为 md 文件时保留 Markdown 缓存；未知、配置、模板、资源变更保守清缓存。所有情况下仍构建完整输出目录并在成功时交换。

基准区分：首次构建、同进程无变更重建、正文编辑、元数据编辑、删除/改名；对照干净全量输出。增加独立可运行的 Go benchmark。真实站点只读，输出与日志写临时目录。

## dev 目录清理追加优化

实际 dev 测量发现目录交换后同步删除旧目录约 550ms，位于刷新关键路径。追加已获同意的后台清理：保持 SwapBuildDir 原同步语义，dev 使用 BuildDirSwapper，一次最多一个后台删除；后续交换前和进程退出时等待清理完成。不得跳过失败回滚或在失败时广播成功刷新。
