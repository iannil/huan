# Admin 鉴权开关（`admin.requireToken`）设计

- 日期：2026-11-18
- 状态：已批准（对话内确认），待实现
- 关联：[ADR 0011 Admin Security Boundary](../../adr/0011-admin-security-boundary.md)（本设计是其 L1/L2 决策面的带日期扩展，ADR 状态保持 Accepted）· [桌面端启动诊断 + 品牌图标设计](2026-11-18-desktop-startup-diagnostics-and-brand-icons-design.md)（桌面端认证对话框现状来源）

## 背景与问题

admin 面板当前**强制** token 鉴权（ADR 0011 L2）：回环 bind 且未设 `HUAN_ADMIN_TOKEN` 时，每次启动自动生成一次性 token 打到 stderr 一次；浏览器端 SPA 收到 401 弹窗索要 token（`web/admin/src/lib/api.ts:82`，存 sessionStorage）。本地单人回环场景（尤其桌面端）每次都要翻 token、粘对话框，摩擦大。

需求（用户 2026-11-18）：**在配置里增加 admin 登录是否需要 token 的开关**。

## 目标 / 非目标

**目标**
1. `admin.requireToken: false` 时：admin API 不再校验 token（SPA 不再弹窗），CLI stderr 不再打印一次性 token，改为输出一行可观测的 disabled 提示。
2. 安全边界不变：**非回环 bind + 关闭鉴权 → 拒绝启动**（延续 ADR 0011 L1 fail-fast，新增专属报错文案）。
3. 缺省 true（安全默认），存量站点零迁移、行为逐字节不变。

**非目标**
- CLI flag（`--insecure-admin` 之类）——配置已覆盖，YAGNI。
- auth 模式枚举扩展（password / oauth——ADR 0011 已列入 v1.x+ YAGNI）。
- audit log（L4）变化——鉴权关闭**不影响**写操作审计，写操作照常记录。
- SPA 改动——弹窗是 401 驱动，鉴权关闭后 API 不再 401，SPA **零改动**。

## 决策记录（对话内确认，2026-11-18）

| 决策点 | 裁决 | 理由 |
|---|---|---|
| 非回环 bind + 关闭鉴权 | **拒绝启动**（否决「允许但警告」） | admin API 可写 content/ 任意文件；LAN 零鉴权暴露正是 ADR 0011 L1 fail-fast 要防的场景，且该 ADR 曾显式否决 warn-and-continue |
| 配置键形态 | 嵌套布尔 `admin.requireToken` | 对齐 `Markup`/`Sitemap` 嵌套模式；布尔无歧义；给未来 admin 域设置留命名空间（否决顶层 `adminRequireToken` 平铺与 `admin.auth` 枚举） |
| `false` 与 `HUAN_ADMIN_TOKEN` 并存 | **开关赢**，env 被忽略 | 单一权威来源，避免「关了还要查 env」的心智负担 |

## 配置语义

```yaml
# huan.yaml（新增段；整段缺省 = true，即现行为）
admin:
  requireToken: false
```

- 解析（`internal/config/config.go`，照搬 `CleanPublishDir *bool` 先例）：

```go
type AdminConfig struct {
    // RequireToken gates the admin API behind a bearer token. Default true.
    // false is only honored on loopback binds (see ADR 0011 L1).
    RequireToken *bool `yaml:"requireToken"`
}

func (c *AdminConfig) RequireTokenEnabled() bool {
    return c.RequireToken == nil || *c.RequireToken
}
```

- `Config` 新增字段 `Admin AdminConfig \`yaml:"admin"\``；`Defaults()` 不需要显式设值（nil → true）。

## 鉴权路径改动

### L1：`CheckBindSafety(bindAddr, token string, requireToken bool)`

新增第三参，判定矩阵：

| bind | requireToken | token | 结果 |
|---|---|---|---|
| 回环 | 任意 | 任意 | ✅ 放行（不变） |
| 非回环 | true | 有 | ✅ 放行（不变） |
| 非回环 | true | 无 | ❌ 拒绝，**现有报错文案逐字节不变** |
| 非回环 | false | — | ❌ 拒绝，**新报错**：明确指出 `admin.requireToken: false` 不能用于非回环 bind（指引：改回环 bind 或删除该配置） |

### L2：`HandlerOptions.RequireToken bool`

- `false` → `/admin/api/*` **不包** TokenMiddleware（api handler 直接挂载）；`true`（含缺省）→ 现行为。
- **必须显式旗标，绝不以「token 为空」推断关闭**：`TokenMiddleware` 在 token=="" 时，空 provided 会通过 `ConstantTimeCompare` 放行——用空 token 推断关闭会引入这个退化路径。

### token 打印点

- `MustPrintAutoGeneratedToken` 保持不变；关闭时调用方**不调用**它，改为调用新增的同级帮助函数 `PrintAuthDisabledNotice()`（单行 stderr：`huan: admin auth disabled (admin.requireToken: false) — loopback only`）。单一打印职责模式与 Task 1（启动诊断计划）的 `PrintWarnings` 一致。

### 三个调用方（均从 `cfg.Admin.RequireTokenEnabled()` 透传）

| 调用方 | 改动 |
|---|---|
| `cmd/huan/dev.go:73` | 透传 CheckBindSafety + HandlerOptions；关闭时跳过 ResolveToken/GenerateToken，改调 PrintAuthDisabledNotice |
| `internal/daemon/daemon.go:358`（`resolveAdminToken`） | 同上 |
| `internal/desktop/server.go:174` | 同上（固定 `127.0.0.1` 回环，矩阵首行恒放行）；关闭时 runtime 标记 token 不可用，供菜单裁剪 |

### 桌面端菜单

- 关闭鉴权时：托盘/应用菜单**隐藏「复制管理 Token」项**（`internal/desktop/menu.go:40`、`:71` 两处——无 token 可复制）；认证对话框因 API 不再 401 自然消失，无需代码。

## SPA / 桌面端影响

- **SPA 零改动**（401 驱动弹窗，`api.ts:82` 起）。
- **桌面端**：关闭时无认证对话框 + 菜单裁剪如上；bundle 与裸二进制行为同源。

## 测试

- **config**（`internal/config`）：`admin.requireToken` 解析（显式 true/false/缺段）；`RequireTokenEnabled()` nil→true。
- **L1 矩阵**（`internal/admin/auth_test.go`）：上表五行全覆盖；非回环+off 断言**新文案**、非回环+true+无 token 断言**旧文案逐字节不变**。

## 验收（人工 + 自动化）

1. 回环 + `false`：serve 启动无 token 行、有 disabled 提示行；`curl` 无 header POST `/admin/api/*` 成功；SPA 打开无弹窗。
2. 回环 + 缺省：与今天逐字节一致（无 token 行差异、SPA 仍弹窗）——回归底线。
3. 非回环 + `false`：拒绝启动，报错为新文案。
4. 桌面端 + `false`：无认证对话框，「复制管理 Token」菜单项消失。
