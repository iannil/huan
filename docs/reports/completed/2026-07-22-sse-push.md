# SSE 实时推送完成报告

> 完成日期：2026-07-22  ·  对标：daemon 持久化进程的实时性优势（SSG 做不到）
> 设计原文：[SSE 实时推送设计](../../superpowers/specs/2026-07-22-sse-push-design.md)

## 1. 概述

为 daemon 增加 SSE（Server-Sent Events）实时推送：把 daemon 内部 EventBus 事件（构建完成、内容变更、插件加载等）实时广播给所有连接的浏览器客户端。daemon 持久化进程的**实时性优势**此前完全未利用（前端只能轮询查询 API 检测变更）。

这是 daemon 运行时能力的最后一块核心拼图——静态服务 + 按需渲染（JIT）+ 内容查询（REST API）+ 实时推送（SSE）。

## 2. 新增依赖

无新增外部依赖。基于标准库（`net/http` SSE、`encoding/json`）+ 已有 daemon EventBus。

## 5. 关键设计决策

1. **SSE（非 WebSocket）** —— 单向推送（服务器→客户端）正好匹配需求；HTTP 原生（text/event-stream），浏览器 EventSource 原生支持 + 自动重连；无握手/ping-pong 复杂度。

2. **全量广播** —— 所有客户端收到所有事件（daemon 事件量小，无带宽问题）；无订阅状态 = 实现最简。客户端自行过滤（EventSource.addEventListener 按类型）。

3. **复用 EventBus** —— 事件源是已有 daemon EventBus，不重新造事件源。`SubscribeBus` 一行桥接。

4. **非阻塞广播 + 慢客户端保护** —— 每客户端带缓冲通道（容量 16），满则丢弃（`select { case ch <- ev: default: drop }`）。慢客户端永不阻塞快客户端。

5. **心跳保活** —— 每 15 秒 SSE 注释行（`:heartbeat\n\n`），防止代理/负载均衡器超时断开空闲连接。

6. **连接数上限** —— `maxClients=1000`，在 `registerClient` 内原子检查（同一锁），超限返回 nil channel → handler 返回 503。无 TOCTOU 竞争。

7. **`registerClient` 原子容量检查** —— Task 1 把 maxClients 检查下沉到 registerClient（返回 nil 表示满），避免 handler 层 ClientCount 预检查的 TOCTOU 竞争。

## 7. 已知限制

- **全量广播**：所有客户端收所有事件（无服务端类型过滤）。客户端自行过滤。未来可加 `?types=` 过滤。
- **心跳间隔硬编码**：15 秒常量，测试需等真实时钟（`TestStartHeartbeat_Broadcasts` 约 15 秒）。未来可注入。
- **无 Last-Event-ID 恢复**：断线重连从头开始（缓冲 16 缓解短暂中断）。
- **无 CORS**：跨域 EventSource 需代理（同源无问题）。
- **`Start`/`SubscribeBus` 非幂等**：多次调用会叠加心跳循环/订阅者（daemon 只调用一次，无生产风险）。

## 8. 后续优化项

- **按类型订阅**：`?types=build,content` 服务端过滤
- **心跳间隔可注入**：测试加速 + 生产可调
- **Last-Event-ID 恢复**：断线续传
- **认证 SSE**：受保护事件需 token
- **CORS**：跨域 EventSource 支持
- **WebSocket 双向**：客户端发指令（触发构建等）
