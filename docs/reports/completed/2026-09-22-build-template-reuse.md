# 全量构建第三轮优化：模板复用与搜索文本处理

日期：2026-09-22。基线提交：`b045d6e`。延续同日上一轮构建性能优化。

## 改动

- `internal/template/context.go`：使用 `sync.Pool` 复用独占的模板执行实例，摊销整套模板 Clone 和 HTML 自动转义分析。每次执行绑定当前 site，归还前清空引用；partial/partialCached 仍执行当前页面数据，不缓存页面结果。模板工厂保持不执行，每个 Renderer 拥有独立池。
- `internal/template/funcs.go`：将 `<[^>]*>` 正则去标签换成等价线性扫描；plainify 预分配输出缓冲；truncate 只扫描至所需字符边界，避免为全文分配 rune 数组。保持畸形标签、空白、HTML 实体、Unicode 和非法 UTF-8 的原有输出语义。
- 无新依赖、配置或 CLI 参数。

## 实测

Apple M5 Max，Go 1.27.1，2959 个 Markdown 文件，双语构建，51 个模板，7245 个输出文件。两个版本分别编译匹配插件，使用空 HUAN_HOME 和临时输出目录。每个版本预热一次，再交替运行三轮；计入旧发布目录清理、所有静态构建插件和 CLI 初始化。

| 指标 | 基线 | 优化后 |
|---|---|---|
| CLI 全程三轮（秒） | 3.443 / 3.458 / 3.494 | 2.219 / 2.207 / 2.184 |
| CLI 全程中位数 | 3.458 秒 | 2.207 秒（耗时减少 36.2%，约 1.57 倍速度） |
| 构建阶段三轮（秒） | 3.421 / 3.435 / 3.471 | 2.197 / 2.185 / 2.162 |
| 峰值 RSS 三轮（MiB） | 463.8 / 451.9 / 514.6 | 481.4 / 478.4 / 440.1 |

内存中位数约增加 3.2%，样本范围重叠，不能声称降低了全站峰值内存。新编译插件首次加载受 macOS 校验影响：优化版本预热轮 CLI 为 4.257 秒，其中构建 2.133 秒。上表是预热后重复全量构建，不代表冷启动时间。

第二轮阶段耗时：双语页面渲染写入合计 1.473 → 0.779 秒，中文 taxonomy 0.321 → 0.072 秒，双语搜索索引 0.627 → 0.341 秒。

## 输出与验证

- `go test ./...` 全量回归。
- `go test -race ./internal/template ./internal/build`：并发上下文隔离、嵌套 partial、不同 HTML/JS 模板交替执行与错误后恢复。
- 正则去标签与旧实现对照 fuzz：1,258,375 次；截断与旧 rune 实现对照 fuzz：1,252,227 次，均通过。
- 预热及三轮构建分别计算所有文件 SHA-256：7236 个稳定文件完全一致，无新增差异路径。
- 基线自身不稳定的 9 个文件：`posts/2023/04/1401/index.{html,md}`、`posts/2025/02/2202/index.{html,md}` 及各自 `en/` 版本，共 8 个重复 slug 输出；另有 `en/sitemap.xml`。这些路径不计入稳定输出等价性结论，未修改站点内容。
- 分配预算测试先在旧实现观察到失败：模板数增加使单次分配 216 → 1434；去标签单次分配 18 次。新实现通过。模板分配预算仅运行于非 race 模式，因为 race 模式会随机丢弃 sync.Pool 条目；并发正确性仍在 race 模式验证。

原始日志、基线/优化程序、配套插件、逐轮测量脚本与结果位于 `/private/tmp/huan-speed-vAZnRq/`，临时文件不作为发布成果物。当前改动为源码优化，未替换系统安装的 huan。发布时主程序与插件需按常规流程一起重编译。

剩余成本包括 Markdown 渲染、页面执行/写入、搜索全文处理、静态插件和输入扫描。本轮没有宣称达到硬件理论极限，也未引入跨构建缓存或跳过任何生产输出。
