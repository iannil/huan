## 修复 huan deploy cloudflare「no deployer plugin available」（跨 .so 能力接口失效）

- 现象：zhurongshuo `./deploy.sh` 的 [3/10] R2 同步、[4/10] Workers 部署报 `no deployer plugin available`；[9/10] 构建、[10/10] 推送正常。
- 排查（systematic-debugging）：`~/.huan/cloudflare.so` 存在且 `plugin.Open`/`InitPlugin` 成功、`Name()="cloudflare"`，但 `plugin.Find[deploy.Deployer]` 空。
  忠实探针（`LoadPlugin`+`any(p).(deploy.Deployer)`）得 `isDeployer=false`。
- 根因（代码级架构 bug，与环境/构建过期无关）：cloudflare 插件 `Deploy(ctx, deploy.Options)(*deploy.Report,error)` 用的是插件模块**自带副本**
  `github.com/iannil/huan-plugin-cloudflare/deploy` 的 Options/Report，而 huan `deploy.Deployer` 要求 `internal/deploy` 的同名类型。
  Go 接口满足要求方法签名**具名类型同包同一**，字段一样但包不同=不同类型 → 不满足接口。`Name() string`（通用类型）能匹配，故 base Plugin 过、名字出得来。
  对照：`ThemePlugin`（d6437b7）改 map-based 通用类型才跨 `.so` 生效；`Deployer` 从未做此改造，契约类型留在 `internal/`，插件因 Go internal 规则无法导入只能自带副本 → 必然不匹配。
- 波及面：`Translator.Translate(ctx,Request)(*Response,error)` 同病（qwen3 有自带副本 `translate/types.go`），`huan translate qwen3` 同样失效；
  `ImageProcessor.Process(outputDir,sourceDir string)error` 只用 string → 正常，image-pipeline 不受影响。
- 修复（用户选「共享 pkg 契约包」方案，对齐 pkg/plugin.Plugin 做法）：
  - 新增 `pkg/deploy/types.go`（Deployer/Options/PagesOptions/R2Options/Report/FileFailure，embed `pkg/plugin.Plugin`）。
  - `internal/deploy/types.go` 改为 `= pkgdeploy.*` 类型别名 → huan 内所有调用点（cmd/huan/deploy.go 等）零改动。
  - cloudflare 插件 plugin.go/pages.go/worker.go 导入改 `huan/pkg/deploy`，删自带副本 `plugins/cloudflare/deploy/`。净 +25/−279。
- 验证：`go build ./...`、`go build -buildmode=plugin` 均过；`go test ./...` 全绿；忠实探针 `isDeployer=true`；
  隔离沙箱（binary→/tmp、cloudflare.so→临时 HUAN_HOME）`huan deploy cloudflare r2 --dry-run` 成功进入 deployer 执行（不再报 no deployer）。
- ⚠ 生效前提（Go plugin lockstep）：pkg/deploy 现为 host+plugin **共享包**，二者必须同源重建，否则 `plugin.Open` 会**显式报版本错**（比旧的静默 isDeployer=false 更好）。

## Hook 契约拆分（修复 .so 钩子失效）— ADR 0014（完成于 2026-07-29）

- 承接上条「后续待办」：三个 .so 插件（seo-injector/sitemap-enhancer/html-injector）实现 `pkg/plugin.Hook`，而 pipeline 断言 `internal/build.Hook`（`*content.Page`）——结构不同接口、无桥接 → **钩子从未被调用**：SEO meta 注入 / sitemap 增强 / 自定义 HTML 注入在真实站点上全是死代码、静默失效。
- **bug 确诊**：`category: static` 非「编译进二进制」，`newPluginRegistry` 仍从 .so 急加载并注册进 registry，但契约不匹配 → 钩子恒不被调用。与 ADR 0013 同 bug 类，方向为运行期接线。
- **决策——契约拆分（非双向 adapter）**：三插件逻辑全在 `OnOutputWritten(ctx, outputDir string)`（纯 string、磁盘后处理），两个页面方法跨 .so 本质无用（.so 拿到装箱不透明 interface{}，无 content.Page 可检视）。故 `pkg/plugin.Hook`（3 方法）→ `PostBuildHook`（embed Plugin + 仅 `OnOutputWritten`，唯一可跨 .so）；`internal/build.Hook`（`*content.Page`）保留为编译期富页面钩子；`internal/plugin` 加别名 `type PostBuildHook = pkgplugin.PostBuildHook`。
- **桥接（Task2 `c9f7c60`）**：`runOnOutputWritten` 在 `h.(build.Hook)` 之外 `else if h.(PostBuildHook)` 调其 `OnOutputWritten`（build.Hook 优先、互斥不重复、错误只 warn）；`runOnContentLoaded`/`runOnPageRendered` 保持 build.Hook-only 不变。`capabilityLabels` 加 `else if PostBuildHook` 分支仍标 `"hook"`。
- **回归测试（直击 bug 现场，TDD 红→绿）**：`internal/build/hook_test.go` 两条——`TestRunOnOutputWritten_InvokesPostBuildHook`（原实现 stub 满足 PostBuildHook 但不满足 build.Hook 被跳过 → 红；桥接后 → 绿）、`TestRunOnOutputWritten_InvokesBuildHook`（编译期路径不回归）。
- **提交**：Task1 `9f08581`（拆契约 + 别名 + doc 注释 + 护栏白名单注释）、Task2 `c9f7c60`（桥接 + 回归测试 + labels）、Task3 `f715b14`（三插件删 no-op 页面钩子、仅实现 PostBuildHook、重编 .so）。三绿：`go build ./...` / 三 .so `-buildmode=plugin` / `go test ./...` 全过。
- 生效同 lockstep：`go install ./cmd/huan` + `scripts/build-plugins.sh` + `cp release/plugins/*.so ~/.huan/`。文档：ADR 0014 + ADR 0013 后续标记 ✅ + `docs/reports/completed/2026-07-28-hook-contract-split.md`。
