## huan build 性能优化（目标 1s，目标口径：全量干净 --noCache）

- 基线：zhurongshuo 双语干净构建中位 4.84s / 10261 文件。
- A1：新增 `languages.<code>.skipProjectStatic`，en 不再把 1502 个共享静态拷进 docs/en → 产物 8763、en static copy 350ms→2ms。
- A2：`FuncMapWithI18n` 把 i18n bundle 闭包进 FuncMap；`Renderer.newWorker` 现在真正重新绑定 funcMap；loader 加 `loadMu`。渲染不再依赖全局 SetI18nBundle。
- A3：双语并行（env `HUAN_PARALLEL_LANGS=1`），staging + rename 合并；A/B 实测仅 -6%，默认关闭。
- 静态拷贝：有界并行 + APFS clonefile，实测无明显收益（瓶颈是 mkdir/open）。
- B1：`build` 默认 GOGC=200（用户 env 优先），中位 3.79→3.21s，代价峰值 RSS ≈600→900MB。
- 新增 `HUAN_CPUPROFILE` 可选 CPU profile 入口、`scripts/bench-io-floor.py`。
- 关键结论：仅落盘 8763 文件/234MB 就要 0.67–0.87s，因此本机 1s 不可达。用户选择「继续纯 CPU 优化，不承诺 1s」。
- **测量教训**：22:05–22:45 的 3.2–4.8s 数字受外部负载（load1 10–19）污染，不可比。低负载（load1 3.4–7.2）同条件 A/B 才有效：改动前 1.86s / 10261 文件 → 改动后 1.72s / 8763 文件。以后每次基准必须记录 load1。
- 验证：`go test ./...` 通过、`-race` 通过、串行 vs 并行输出 8763 文件逐字节 0 差异。
- 待决策：seo_injector 的 `OnOutputWritten` 会重读全站 HTML（CPU 1.0s），优化需改插件契约。
