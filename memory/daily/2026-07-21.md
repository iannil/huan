- 方案 C：DAG 驱动 + pipeline 状态复用

- final review 发现并修复两个 Critical 正确性缺陷：
  - **C1 DAG 依赖方向反了**：列表页编辑文章后静默过期。翻转边语义（聚合页 DependsOn 文章）
  - **C2 站点级输出不重建**：sitemap/search/RSS 过期。IncrementalRender 末尾调用 renderFeedsAndSpecials 子集

### 关键经验

- **设计文档的 PageLookup/ContextLookup 缓存方案有正确性风险**：内容变更时 context 引用的 page 指针失效。务实调整为只缓存渲染基础设施，重建内容+context。设计阶段难以完全预见这类引用失效问题。
- **DAG 依赖方向容易搞反**：需要明确"谁依赖谁"。聚合页（section/tag/home）显示文章，所以聚合页 DependsOn 文章。final review 通过实际的端到端测试（编辑文章 → 检查列表页输出）才发现这个缺陷。
- **Watcher 与 DAG 的路径格式不匹配是隐蔽 bug**：fsnotify 给绝对路径，DAG 存相对路径，AffectedBy 直接查表返回空，增量构建静默 no-op。需要路径归一化层。
- **Subagent-driven development 流程有效**：每个 task 独立 subagent + review，Critical 缺陷在 final review 被独立 subagent 实际复现，而不是依赖实现者自检。
