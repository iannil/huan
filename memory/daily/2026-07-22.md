### 关键经验

- **JIT 与增量构建共享 PipelineCache** —— 两者都是"重建内容+context，复用缓存模板"，职责分离（一个写文件一个返回 HTML）。缓存设计要考虑多消费者。
- **公开 API 的安全边界要独立于开发标志** —— `GenerateContentAPI` 原本用 `p.opts.IncludeDrafts`，导致 daemon `--buildDrafts` 时 draft 泄露到公开 API。公开 API 契约必须独立于开发模式标志。final review 通过 `BuildDrafts=true` 的回归测试才发现。
- **字节计数 vs rune 计数** —— 中文站点的长度限制必须按 rune 计数（`utf8.RuneCountInString`），否则 67 个中文字符（201 字节）被误杀。
- **公开端点的整数溢出是 DoS** —— `page=MaxInt64` 导致 `(page-1)*limit` 溢出为负值，绕过边界守卫，slice panic。公开端点的所有数值参数都要做溢出/负值守卫。
- **预构建数据源 + 运行时查询层** —— 不重新造数据源（复用 contentapi JSON），daemon 只做查询层（过滤/分页/聚合），与增量构建天然协同。比"运行时常驻 site 对象"简单且无引用失效问题。
